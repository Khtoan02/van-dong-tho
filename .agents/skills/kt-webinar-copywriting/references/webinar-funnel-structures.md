# Webinar Funnel Structures

Select the page by combining two independent dimensions:

1. Access behavior - live, evergreen/on-demand, or hybrid.
2. Commercial type - free or paid.

Never use live language or commercial terms that are not supported by approved facts.

## Seven-section Base Registration Page

Use this base for both free and paid webinars:

1. **Hero Section** - present exactly three complete Hero options before selecting one for the assembled page.
2. **Why Attend** - answer why the target ICP needs this webinar now using approved problem and mechanism facts.
3. **Benefits** - describe practical learning outcomes or decisions.
4. **Timeline/Agenda** - show approved topics and sequence.
5. **Who It Is For** - define the audience and fit clearly.
6. **Event Details + Registration Form** - concise bullets for date, time, timezone, place/platform, host, and format; include complete form microcopy.
7. **Expert Profile** - use approved biography, credentials, experience, and proof only.

Each section must answer a different question. Use placeholders for missing facts.

## Commercial Type A - Free Webinar

Use the seven-section base without price or payment claims. CTA accurately describes free registration only when the event is confirmed free.

Possible CTA patterns:

- `Đăng ký tham dự miễn phí`.
- `Giữ chỗ tham dự` only when capacity/seat behavior supports that wording.

## Commercial Type B - Paid Webinar

Use the same seven-section base and add a **Pricing, Offer, and Conditions** section containing only approved facts:

- Price and currency.
- What the ticket includes.
- Payment method/terms.
- Bonuses when approved.
- Refund or guarantee policy when approved.
- Deadline, capacity, or eligibility when real and approved.
- Paid registration/purchase CTA.

The paid section does not replace Why, Benefits, Agenda, Audience, Details/Form, or Expert Profile. If a critical commercial fact is missing, mark it explicitly and do not improvise.

## Access Behavior A - Live

Use when a host presents at a confirmed date and time. The page and messages must use one exact event datetime and timezone.

Lifecycle normally includes confirmation, calendar action, Zalo invitation when approved, the fixed live reminder schedule, attendee follow-up, and no-show follow-up.

## Access Behavior B - Evergreen or On-demand

Use when registrants can watch immediately or through automated access behavior. State access behavior accurately. Do not use the live countdown schedule.

Avoid `gặp trực tiếp`, `tham gia live`, `phòng đã mở`, or `chỉ diễn ra một lần` unless true.

## Access Behavior C - Hybrid or Scheduled Evergreen

The brief must state:

- Whether each phase is actually live.
- How time slots are generated.
- Whether chat/Q&A is live, simulated, or unavailable.
- Whether replay exists.
- Which messages belong to the live phase and evergreen phase.

Write separate variants when behavior changes. Never imply the host is present in a recorded experience.

## Three Mandatory Hero Angles

Every output contains exactly three complete Heroes. Use distinct persuasion angles while preserving the same facts:

1. Outcome/transformation.
2. Problem/relevance/approved urgency.
3. Mechanism/expert/distinctive experience.

Each Hero includes headline, subheadline, event/access facts, CTA, and essential reassurance or paid price cue where appropriate.

## Message Hierarchy

The assembled page must make these answers easy to find:

1. What is the event?
2. Who is it for?
3. Why should this ICP attend?
4. What will they learn or be able to do?
5. Who is teaching and why are they relevant?
6. When and how is it accessed?
7. What action is required now?
8. If paid, what is the exact offer, price, and condition?
