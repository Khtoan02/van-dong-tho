# Webinar Sequence Timing Guide

Use approved event start datetime and timezone as the single source of truth. For live webinars, compute and print the exact send date, local time, and timezone for every active message.

## Live Webinar Default Schedule

The following schedule is approved as the default and must not be replaced with approximate alternatives:

1. **Immediately after registration** - confirmation, event facts, Zalo action when approved, and Google Calendar action.
2. **Warm-up 1-2 emails within T-7 days to T-5 days** - send one or two emails highlighting the webinar's distinctive value and preparing the ICP.
3. **T-3 days** - exact three-day countdown.
4. **T-1 day** - exact one-day countdown.
5. **T-5 hours** - five-hour notice, Zoom/access link placeholder, and preparation guidance.
6. **T-1 hour** - one-hour notice with concise access CTA.
7. **T-15 minutes** - room-open notice and check-in CTA.
8. **After event** - separate attendee and no-show follow-up.
9. **Replay/expiry/offer** - only when approved facts authorize them.

## Warm-up Placement

- Schedule one or two warm-up emails inside the window from 7 days before to 5 days before the event.
- If two emails are used, choose separate exact timestamps inside that window; do not schedule them at the same time.
- Use one email when the available content or campaign window does not justify two.
- Warm-up content should reveal one or two distinctive points, increase readiness, and avoid repeating countdown copy.

## Exact Countdown Rules

- `T-3 days` means exactly 72 hours before the approved event start.
- `T-1 day` means exactly 24 hours before.
- `T-5 hours` means exactly 5 hours before.
- `T-1 hour` means exactly 1 hour before.
- `T-15 minutes` means exactly 15 minutes before.
- Preserve the event timezone in the schedule and message fact block.
- Do not round to a convenient clock time unless the approved event schedule or Project Lead explicitly changes the send rule.

If registration or funnel launch occurs after a scheduled point, mark that item `SKIP - timing passed`. Do not send retroactively and do not shift the interval.

## T-15-minute Content

State that the room is open only when implementation confirms that behavior. Invite the registrant to enter and check in. Use an explicit placeholder when the final join link is pending.

## Evergreen and Hybrid Rules

Evergreen sequences follow actual access behavior rather than the live countdown schedule. Hybrid funnels use the live schedule only for confirmed live phases; recorded phases use evergreen consumption reminders.

Never use fake start times, fake host presence, or false replay expiry.

## Message Requirements

Each message includes:

- Segment.
- Channel.
- Exact send datetime and timezone, or `SKIP - timing passed`.
- One objective.
- Event fact block when relevant.
- Final production-ready body.
- One primary CTA.
- Required link placeholder.

## Post-event Segment Rules

### Attended

Reference supplied teaching content accurately and use the approved next step.

### No-show

Acknowledge the missed session without shame. Offer replay only when confirmed.

### Watched replay

Use only when tracking supports the segment.

### Did not take the offer/next step

Address one approved objection per message. Preserve exact price, deadline, eligibility, guarantee, bonus, and payment terms.

## Channel Adaptation

- Email may use subject, preview text, body, and CTA.
- SMS must be concise and identify the sender/event.
- Zalo/Messenger should use natural chat language and short blocks.

Rewrite for each channel instead of mechanically shortening email copy.
